# Decisions

Each decision is numbered and stays here even when superseded, with a note on what replaced it. Open questions move here once they are answered.

| # | Decision | Choice | Why |
|---|---|---|---|
| D1 | Home | A Liminal HQ Labs experiment in `liminal-hq-labs/undertone-sound`, public from the first commit | Try the idea in the open before it earns a place in Liminal HQ |
| D2 | Licence | `Apache-2.0 OR MIT` | House licence, compatible with both ecosystems |
| D3 | Dependency updates | No Dependabot configuration until the project opts in | Labs repositories stay quiet by default. See the [Labs charter](https://github.com/liminal-hq-labs/.github/blob/main/docs/labs-charter.md#dependabot-is-opt-in) |
| D4 | Family and names | Undertone is a family: `undertone` (the TypeScript library, its own repository), `undertone-dsp`, `undertone-mini`, `undertone-opl` and `undertone-sound` (crates here), and `oplstream`, which stays unprefixed | `oplstream` names a format library that is useful without Undertone. Nothing is reserved on crates.io yet |
| D5 | First crate | `oplstream` is the reference implementation of OPX: reader, writer, stepper, validator, text twin, and IMF, DRO and VGM import | OPX is the DOS sound format and the core's register-stream format |
| D6 | OPX specification | `docs/OPX.md` lives here and moves with the crate; Fizz 2's docs point at this repository | The spec and its reference code change together. Maintainer's call, 2026-11-18 |
| D7 | Fizz-agnostic core | Fizz concepts (rooms, role pans, the level rule, captions, cue sheets, mix profiles) live in a separate Fizz layer outside this repository | A second consumer, City Sim 1000, shares Undertone. VoiceParams field names and builder method names are frozen, and any Rust or WebAssembly backend is opt-in |
| D8 | Neutral wording | Superseded 2026-11-18: the project carries no variant word of that kind. Names say what a thing is, and nothing here depends on the studio's old wording | The word described one Fizz 1 song variant; it has no value as a mode, format or name |
| D9 | Publishing | Every crate has `publish = false` until the maintainer says otherwise. Names are planned for crates.io but not reserved | Publish deliberately, with versions and a release flow decided first |
| D10 | Sound-effect channels | Channels 5 and 14 are the sound-effect channels on OPL2 and OPL3, passed in as reserved channels rather than hard-coded in the core | Fizz's choice; the core stays agnostic |
| D11 | Relicensing the carved crates | Crates carved from the Fizz Audio Studio are relicensed from MIT to `Apache-2.0 OR MIT`, and their SPDX headers change with them | The maintainer approved it on 2026-11-18, and this repository's licence is D2. The copyright line is unchanged |
| D12 | `undertone-mini` | It holds Undertone's mini-notation (parser, pattern combinators, exact fractions) and, as `js`, the JavaScript number and string semantics (`String(n)`, `toFixed(2)`, `Math.round`, `trim`, UTF-16 lengths, `JSON.stringify` quoting). `undertone-dsp` depends on it | Both exist so Rust output matches the TypeScript golden fixtures, and the mini-notation crate depends on nothing |
| D13 | What stays in the studio | The glue that turns a studio `Song` and `Performance` into Undertone voices and score events (`presets` and `studio`), and the comparison harness against the MPL-2.0 `web-audio-api` crate (`reference`), stay in the Fizz Audio Studio, which depends on `undertone-dsp` | This repository is Fizz-agnostic (D7) and keeps its default build free of an MPL-2.0 dependency. The allocation-counting streaming test also stays there, because it needs `unsafe` for a global allocator |
| D14 | Twin assembler needs `alloc` | `print_twin` is in the `no_std` core; `assemble` (twin text to bytes) needs `alloc` | A parser that produces bytes has to allocate. The specification lists both in the core |
| D15 | Other chips in a VGM file | A VGM file is refused when its header names no YM3812 or YMF262, names both, or sets the dual-chip flag. Other chips' commands inside an OPL file are dropped, counted in the import report, and their waits kept. An unknown VGM opcode is refused | The specification says other chips' commands are "dropped and reported" |
| D16 | Reader versions | A reader accepts major 0 with minor 0 or 1 and refuses a higher minor. `LOOP` while the tier is 1, and core writes to bank 1 when flag bit 0 is set, are refused. A loop point that lands on the `END` tick is refused | The most literal reading of the specification. Raise a question in the specification when a real file disagrees |
| D17 | Re-timing | Halves round up. "Writes moved" counts register and speaker writes whose tick did not map exactly. Markers and the loop point are re-timed but not counted | One rule, reported, never silent |
| D18 | CI shape | One job per check in the shared `ci-rust` image pinned by digest (format, Clippy, tests, doc tests, docs, `oplstream` feature tiers, `no_std` build, WebAssembly build, dependency licences, advisories), plus markdown, headers, shell, workflow and banner checks on the runner | A failing pull request names exactly what broke. No single validate job. Dependabot stays off |
| D19 | Documentation site | VitePress with Bun in `site/`, deployed to GitHub Pages from `main` by `.github/workflows/pages.yml`. The specification, behaviour, roadmap and decisions pages are rendered from `docs/OPX.md`, `SPEC.md`, `docs/ROADMAP.md` and `docs/decisions.md` by include, so each stays the single source and no copy is committed. The Rust API is `cargo doc` output copied into the site under `api/` by `scripts/build-site.sh`. The guide pages show snippets from an example in each crate (`examples/*_guide.rs`), which the test build compiles | The house pattern from Undertone's own site, in this project's colours. Documents that live in the repository for readers on GitHub should not fork. Compiled snippets cannot drift from the API. The site builds on every pull request in one `Docs site` job and deploys only on `main` |
| D20 | WebAssembly bindings | `crates/undertone-wasm` (`cdylib` and `rlib`, `publish = false`) exposes the crates to JavaScript with `wasm-bindgen` pinned at `=0.2.125`, the version of the `wasm-bindgen` tool in the shared `tauri-ci-desktop` image. `scripts/build-wasm.sh` refuses to run when the two differ. The logic is plain Rust in modules tested natively, and the exported layer is thin. Failures cross as thrown strings | A version mismatch between the crate and the tool is a runtime failure, so it is checked first. Native tests keep the logic out of the browser |
| D21 | OPL emulator and `unsafe` | The player uses `oplon` `=1.0.0` (MIT, `no_std`, integer-only OPL2 and OPL3), the emulator the studio plays OPL with. No `unsafe_code` exception is needed: the workspace's `forbid(unsafe_code)` compiles with `wasm-bindgen`'s macros on native and `wasm32` targets | The licence is already allowed by `deny.toml`. If a later `wasm-bindgen` needs an exception, scope it to `undertone-wasm` and record it here |
| D22 | Demo page | `site/demo.md` renders the whole stream through `Player` in blocks on the main thread, then plays it as one `AudioBuffer`, and shows the peak it rendered. Only Title Theme, the maintainer's own composition, is bundled, imported by Vite from `fixtures/opx/title-theme.imf` so no copy exists. Other songs are dropped in by the visitor and never leave the browser | The simplest approach that is exact and checkable. No third-party game music is bundled |
| D23 | Readable errors | `HeaderError`, `DecodeError` and `ValidationError` implement `Display`, in the `no_std` core | A page or a tool shows why a file was refused without matching on enums |
| D24 | CI for the bindings | A `WebAssembly bindings` job runs `scripts/build-wasm.sh` (the release build and `wasm-bindgen`) in the `tauri-ci-desktop` image, which carries the `wasm32` target and the pinned `wasm-bindgen`. The `Docs site` job and the Pages workflow run the same script through `scripts/build-site.sh`, so the demo ships in the site | One job per check, as D18 says |
| D25 | DSP provenance wording | `undertone-dsp` documents that it implements the specification's algorithms and matches Chromium's behaviour. It does not claim a clean-room derivation, and the compressor stays `Apache-2.0 OR MIT` | The compressor's provenance against Chromium's BSD-3-Clause kernel is unverified, so the wording claims only behaviour. The maintainer decided the licence, 2026-11-18 |
| D40 | Test results on pull requests | [pr-results](https://github.com/liminal-hq-labs/pr-results) v0.2.0, pinned by commit SHA, posts one comment and a check run per suite. CI jobs only upload reports as artefacts: nextest JUnit (`ci` profile in `.config/nextest.toml`, one retry so a flaky test is reported as flaky) and a step report from each job, written by `scripts/step-report.sh`. `.github/workflows/publish-test-results.yml` publishes from a `workflow_run` trigger. Job names, and so check names, stay as they were | The repository is public, so fork pull requests get a read-only token and in-job publishing cannot post for them. The publisher holds the write tokens, runs from the default branch and never checks out pull request code. The existing jobs stay split, one per check (D18) |
