# Fixtures

Golden files the Rust crates are checked against. `mini/`, `undertone/` and `chips/` are recorded from Undertone's TypeScript implementation and a Rust port must reproduce them exactly. `song/` and `opx/` are written by the Rust crates in this repository (`opx/` is also held to the game's own chunk). None is edited by hand.

- `mini/` — Undertone's `mini` run over every pattern a song or a test holds, plus edge cases and errors. One file per group, each an array of cases with an `id`, `group`, `from` (where the pattern came from), `pattern`, `leaf` and either `queries` or `error`. Run by `crates/undertone-mini/tests/fixtures.rs`. The `leaf` rule is `word` (accept every word), `pitch` (a note name whose MIDI number is 12 to 120) or `drum` (one of `crash openhat hat clap rim snare tom kick`).
- `undertone/graph.json` — the Web Audio graph Undertone's `playVoice`, the orbit buses and the master bus book for three scores, recorded call by call: every node made, every AudioParam call, every connection, start and stop times, and a summary of every buffer and periodic wave. Each case carries the score it was booked from, one line an event with each distinct voice listed once. `crates/undertone-dsp/tests/fixtures.rs` reads the score back, books it on `LogGraph` and requires the whole graph to match byte for byte. The scores are the cases `voices` and `corners` (96 ticks a second) and `title-theme` (112 ticks a second).
- `opx/title-theme.imf` — Fizz 1's Title Theme as the DOS game plays it: one Type-1 IMF chunk (a two-byte length, then four-byte records of register, value and a little-endian delay) at 560 Hz, 3,312 records and 34,560 ticks. It is song 0 of the game's sound bundle, copied byte for byte, and it is the maintainer's own composition, committed with his approval. `crates/oplstream/tests/title_theme.rs` imports it, validates it, round-trips its text twin and re-times it. It is the only real file the importers have met so far; there are no real DRO or VGM captures yet.
- `song/` — the song document's cases, **written by this repository**: `crates/undertone-sound/tests/` computes each file from the cases it holds and requires the file to hold exactly those bytes. The format id is `undertone-sound/song`. The named songs the cases use are in `inputs/<name>.song.json`, each exactly as the formatter writes it, keys in document order. `validation.json` is `validate_song` over good and broken documents (`input`, `ok`, `problems` as `{ severity, path, message }`, in the order produced); `formatted.json` is the formatter over each song and over values that hit each rule (the 90-column inline limit, escapes, empty containers, number forms); `compile.json` is the compiler for the whole song, each section, arrangement entries and take overrides (a `performance` is `{ stepsPerSecond, lengthSteps, events, sections }`; steps and lengths of mini-notation takes are doubles computed as `Fraction.toNumber() * stepsPerBar`, in the same order of operations as Undertone's TypeScript); `music.json` is pitch names, MIDI numbers, spelling, scales and the format's constants; `model.json` is the small song helpers. A text that must be exact is an array of lines, joined with newlines, and a final empty string means a trailing newline. An error is a case with `error` holding the message word for word. To change a file, change the code or a case's input and run `UPDATE_FIXTURES=1 cargo test -p undertone-sound -- --test-threads=1`, then read the diff: it is what the change did. The cases began as the TypeScript implementation's recordings and were migrated to this format (the format id, the author objects and the ten presets) by rewriting their inputs and letting the code write the results; the compile results did not change.
- `chips/` — the OPL2, OPL3 and PC speaker code over the named songs of `song/inputs/` and five songs of its own in `chips/inputs/` (`chips-dense`: more simultaneous notes than any chip has channels; `chips-overrides`: voice overrides that are out of range, fractional, the wrong type or null; `chips-panning`: every zone of the OPL3 pan law under a −1.5 dB law; `chips-priority`: priorities that contest channels; `chips-host-patches`: the three presets `bass`, `pad` and `organ`, whose patches the host replaces for this song only). The song documents in `chips/inputs/` carry the song format id and are written in the song style, which the song tests check; the results beside them are TypeScript recordings. `chips-host-patches` is the recorded `chips-fizz` with its three instruments naming `bass`, `pad` and `organ` in place of the retired presets, and the host plays the same patches, so the recorded results are unchanged apart from the song's name. A case's `input` names the song and `options` is the compile option (`section` or `only`) or `null`. Run by `crates/undertone-opl/tests/fixtures.rs`, which plays the host: it reserves channels 5 and 14 and, for `chips-host-patches`, supplies the three patches. `opl2.json` and `opl3.json` are `sequenceOpl`: `seconds`, the `dropped` count, `droppedEvents` as indexes into the compiled performance's `events`, and `writes` as `[time, register, value]` in order (a value is not always a byte: the chip takes it modulo 256). `speaker.json` is `sequenceSpeaker`: `frames` and `runs`, the per-frame frequencies (`f32` values) as `[hz, count]` runs. `lost.json` is the lost-note analysis on each chip for every song, `null` when nothing is lost; `demand` and `lost` are one number per song step, joined with commas. `pan.json` is the pan law over pans and laws; its `placements` are readouts the studio draws and are not read here. `registers.json` is the `midiToHz`, `fnumber`, `pitHz` and `attenuation` tables and the channel constants. `render.json` is renders at 11 025 Hz by the TypeScript implementation's WebAssembly chip: the number of `frames`, a `blocks` summary (`[peakL, rmsL, peakR, rmsR]` per `blockFrames` frames, rounded to 8 places) over the whole pass, and an `excerpt` from the loudest block as space-separated samples rounded to 7 places (`right` is `null` for the speaker, whose channels are equal); a port matches within 1e-6.
- `opx/title-theme.opl2.opx` and `title-theme.opl3.opx` — the Title Theme as `undertone-opl` writes it: `song/inputs/title-theme-dos.song.json` compiled, sequenced for each chip under the game's profile (channels 5 and 14 reserved, 560 Hz, the game's level rule, six steps of headroom and its drum holds) and written with `oplstream`'s `Writer`; 34,560 ticks, 644 notes and 316 drum hits on the OPL2, 676 notes on the OPL3. Each has its text twin beside it (`.opx.txt`). They are written by `cargo run -p undertone-opl --example title_theme_opx`, never by hand, and `crates/undertone-opl/tests/title_theme_opx.rs` regenerates them and requires the same bytes, checks both with `oplstream::validate` and compares the OPL2 stream with `title-theme.imf`. The input song is the maintainer's own composition, committed with his approval.

## Conventions

- **Readable JSON, tabs, a trailing newline.** Keys are sorted, and a flat object or array stays on one line up to 200 characters. Nothing carries a timestamp.
- **Numbers.** JSON numbers are doubles, written the way JavaScript prints them (`0.30000000000000004`, `1e+21`). A negative zero is written `0`.
- **JavaScript behaviours a port must copy.** `Math.round` rounds ties toward positive infinity (`-0.125` to `-0.12`, where Rust's `round` gives `-0.13`); string positions and lengths are UTF-16 code units; `trim()` and the `/i` flag follow JavaScript's rules. `undertone_mini::js` holds these.
- **Where they are recorded.** `mini/`, `undertone/` and `chips/` come from the TypeScript reference implementation: Undertone's TypeScript library (`@liminal-hq/undertone`), which holds `playVoice`, `score()` and the mini-notation, driven by the recorder in the Fizz Audio Studio's `tools/fixtures/` (`undertone.ts` and `undertone/recorder.ts`, which wraps an `OfflineAudioContext` and writes each call down). The studio also writes the songs the scores were compiled from. Regenerating those files is done there, not here; the Rust crates only read them. `song/` and `opx/` are regenerated here.
